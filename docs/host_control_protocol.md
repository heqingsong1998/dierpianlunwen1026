# 黏附足上位机控制与测时协议 v1

## 下位机行为

- `Task_Control` 继续每 16 ms 读取两片 AD7142，每片 10 个 stage。
- 保留 `offset1/offset2` 清零补偿和原来的整数通道组合。力标定、多项式计算、力阈值判断已移交上位机，下位机没有自动释放分支。
- PA4 开机电平沿用 `main.c` 的高电平设置。此后仅有效的上位机 LOW/HIGH 命令会写 GPIO；HOLD 和清零保持现有输出。
- ISR 只接收、验证、记录 D、入队并唤醒 CAN 任务。CAN 任务执行命令、记录 GPIO 写入时间、发送反馈；不再等待下一次 16 ms 采集循环。
- 采集任务仍比 CAN 任务优先级高，因此命令可能等待当前采集处理结束。实际等待可由反馈时间戳计算。
- 清零在下一次采集时用当前 20 个 stage 的读数更新基准，完成后 `baseline_generation` 加 1。清零反馈中的 ZERO_PENDING 仅表示已排队，不能当作已经完成；观察后续 `0x124` 的基准版本确认完成。

## 时钟与关联

- TIM2 专用于 1 MHz 自由运行的 32 位计数，不占 GPIO，不改动 HAL 的 TIM6 时间基准。
- `*_us` 均为单片机本地微秒计数，分辨率 1 us，不代表已与电脑同步或具有 1 us 绝对精度。
- 时间戳每约 71.58 分钟回绕。差值使用 `(later - earlier) & 0xFFFFFFFF`。
- 采样帧编号为 uint32，从 1 开始，0 表示未关联采样帧。编号回绕时跳过 0。
- 下位机保留最近 128 帧的 A 和基准版本，连续采样时约覆盖 2.048 秒。超出历史范围的关联命令会被拒绝，原输出保持。电脑应处理新帧，并用产生决策的帧编号下发。
- 清零之前的帧也会被拒绝。清零后的算法状态/缓存重置由上位机负责。
- 所有多字节载荷字段均为小端，按字节编码，不直接传 C 结构体。

## 上行 `0x123`：48 字节，兼容原数据显示

CAN 标准 ID，CAN FD，无 BRS。前 16 个 int16 通道值的排列与旧版一致，均来自清零补偿后的数字量，不是已标定的力。

| 字节偏移 | 类型 | 内容 |
|---|---|---|
| 0～31 | 16 × int16 | 原来的 Fx1、Fy1、Fz1、Mx1、My1、App11、App12、Fx2、Fy2、Fz2、Mx2、My2、App21、App22、重复的 Fz1、重复的 Fz2 |
| 32～33 | uint16 | 原 `flag_fz`，固定 0，已取消本地阈值判断 |
| 34～35 | uint16 | 原 `flag_fx`，固定 0 |
| 36～37 | uint16 | 输出状态：0=启动后尚未写入控制电平，1=最近命令拉低，2=最近命令拉高；0 不表示自动控制 |
| 38～39 | uint16 | PA4 当前电平，0/1 |
| 40～43 | uint32 | `sample_sequence`，占原 int16 索引 20、21 |
| 44～47 | uint32 | `ready_us`：A，占原 int16 索引 22、23 |

A 在清零补偿、通道组合完成后记录，位于采集结果入队、CAN 打包和发送之前，因此传输合计包括此后的下位机发送排队。

旧上位机把最后四个 int16 当作保留值显示，不会解释为帧编号/时间。新上位机应按 uint32 解析，不能把带符号 int16 直接拼算而不做掩码。

## 上行 `0x124`：32 字节

| 字节偏移 | 类型 | 内容 |
|---|---|---|
| 0～15 | 8 × int16 | 原有八组 stage 对和，顺序不变 |
| 16～19 | uint32 | 与 `0x123` 相同的 `sample_sequence` |
| 20～23 | uint32 | 与 `0x123` 相同的 A |
| 24～25 | uint16 | 本帧 `baseline_generation` |
| 26～27 | uint16 | 协议版本，1 |
| 28～29 | uint16 | 命令队列满导致的累计丢弃数，低 16 位 |
| 30～31 | uint16 | CAN 发送失败/重试超时累计数，低 16 位 |

两帧按编号配对，不依赖到达先后。这里上传的是原有通道组合及八组对和，尚不是 20 个 stage 的逐通道原始值。

## 下行命令：扩展 ID `0xFFFE`，严格 8 字节

继续使用现有上位机的 CAN 转串口封装和 ID。非此 ID、远程帧、非八字节载荷和非法命令都会被忽略。

### 新版关联命令

| 字节偏移 | 类型 | 内容 |
|---|---|---|
| 0 | uint8 | 固定 `0xC1` |
| 1 | uint8 | 动作：0=拉低，1=拉高，2=保持，3=请求清零并保持输出 |
| 2～3 | uint16 | `command_id`，电脑为每次发送分配，配合帧编号唯一关联 |
| 4～7 | uint32 | 所依据的 `sample_sequence` |

帧编号 0 允许无采样关联的手动控制，但没有有效 A，不能据此计算传输合计。测时实验应使用一帧真实新数据的非零编号。

例如：基于第 1 帧、命令号 1，拉高 PA4，CAN 载荷为：

```text
C1 01 01 00 01 00 00 00
```

沿用现有上位机串口封装后为：

```text
5A 08 04 00 00 FF FE C1 01 01 00 01 00 00 00 A5
```

0/1 表示电平，不在协议中假定哪个电平对应机械释放。

### 旧版按钮兼容

仍接受首字节 `A4/A5` 的旧载荷：第 1 字节 0=拉低、1=拉高、2=保持；第 2 字节 1=请求清零。原来的模式 2 已取消“恢复自动阈值控制”的语义。

- 现有“回复”按钮：拉低。
- 现有“吸合”按钮：拉高。
- 现有“清零”按钮：请求更新基准，保持电平。

这些命令没有帧编号，反馈带 LEGACY 标志，不能用于传输合计测量。

## 上行反馈 `0x125`：32 字节

每个入队并被 CAN 任务处理的合法命令产生一帧反馈。反馈发送发生在记录 D/GPIO 时间之后，反馈自身的回传时间不进入 `D-A`。

| 字节偏移 | 类型 | 内容 |
|---|---|---|
| 0 | uint8 | 协议版本，1 |
| 1 | uint8 | 状态：0=接受，1=找不到关联帧，2=帧属于旧基准；非 0 时不执行动作/清零 |
| 2 | uint8 | 请求动作 0/1/2/3 |
| 3 | uint8 | 当前 PA4 电平 |
| 4～5 | uint16 | `command_id` |
| 6～7 | uint16 | 标志位，见下表 |
| 8～11 | uint32 | 关联的 `sample_sequence` |
| 12～15 | uint32 | A：该帧数据准备时间，无关联时 `0xFFFFFFFF` |
| 16～19 | uint32 | D：RX 中断内完成合法命令解析的时间，位于命令排队/执行之前 |
| 20～23 | uint32 | GPIO 写寄存器后的时间；未写 GPIO 时 `0xFFFFFFFF` |
| 24～27 | uint32 | `round_trip_us = (D-A) mod 2^32`，无有效关联时 `0xFFFFFFFF` |
| 28～29 | uint16 | 反馈时的基准版本 |
| 30～31 | uint16 | 累计命令队列丢弃数，低 16 位 |

| 标志掩码 | 名称 | 含义 |
|---|---|---|
| `0x0001` | TIMING_VALID | A、D、round_trip 有有效采样关联 |
| `0x0002` | GPIO_WRITTEN | 本命令已写 GPIO；重复写相同电平也会置位 |
| `0x0004` | ZERO_PENDING | 已请求清零，等待采集任务完成 |
| `0x0008` | LEGACY | 来自旧按钮命令，无帧编号 |
| `0x0010` | GPIO_CHANGED | 本命令改变了输出电平，避免把重复同电平命令当作新的机械动作 |

最多缓存 8 条命令。队列满时新命令被丢弃、不执行，也不生成对应反馈；丢弃计数在后续遥测/反馈中报告。CAN FIFO 满会在任务中有界重试最多约 5 个 RTOS tick，失败计数可见，不进入 `Error_Handler` 卡住采集。

## 上位机配套接口与三个指标

`smzcode/apps/main_window.py` 对应的上位机现已支持三种上行帧、真实帧/配对帧记录、新版命令及反馈匹配。具体文件和接口见 `smzcode/docs/protocol_v1.md`。独立算法控制器和六轴力稳定判据仍需后续实现；手动按钮不产生虚构的控制器处理时延。

1. 收到一帧真实新数据，解析编号/A，将未标定的清零数字量交给控制器，使用 `perf_counter_ns()` 记录 B。勿把同步保存中重复使用的缓存行当作新输入。
2. 控制器完成标定/算法/决策，在提交发送的同一出口记录 C，命令携带原帧编号与命令号。
3. 接收 `0x125`，按命令号和帧号匹配，只对状态 0 且 TIMING_VALID 置位的数据计算：

```text
controller_us = (C_ns - B_ns) / 1000
transport_sum_us = round_trip_us - controller_us
gpio_wait_us = (gpio_written_us - received_us) mod 2^32  # 仅 GPIO_WRITTEN 时
```

单片机与电脑计时频率要正确，原始时间与无效结果应保留。不能把上位机函数返回时间、`flush()` 返回或发送后的 `sleep(0.01)` 当成 D。

第 3 类“近似执行时延”仍在上位机用同一电脑时间轴计算“C → 六轴力稳定数据的接收时间”，保留此前约定的下传/观测链路影响。GPIO_CHANGED 可帮助识别本次确实产生了电平动作，但不能代表机械已经完成。

## 验证

- `MDK-ARM/20x30_RTOS.uvprojx`：使用原 ARMCC 5 工程编译。
- `tests/firmware/run_tests.ps1`：用本机 MinGW GCC 运行实际 `app_freertos.c` 的硬件/RTOS模拟回归；覆盖不再自动改变电平、旧通道映射、关联反馈、小端格式、计数回绕、清零保持电平、旧基准/过期帧拒绝、RX过滤及队列溢出、有界发送重试。
- 此验证不替代板上 CAN 转串口兼容、计时频率和实际电磁铁动作测量。构建生成 HEX，不自动烧录。
