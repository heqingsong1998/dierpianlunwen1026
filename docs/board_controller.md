# STM32 板端黏附控制

## 运行实验

1. 用 Keil 编译并烧录本工程。打开上位机并连接黏附脚，等待控制面板显示 STM32 策略、配置编号和模型标识。连接六轴力用于对照记录。
2. 在「STM32 板端控制器」选择策略、阈值和 PA4 触发电平。做两策略对照时，两组均勾选训练标定，使用同一套联合标定、阈值和输出电平。需使用新标定做实测阈值实验时，重载上位机标定并取消勾选训练标定。
3. 用「回复」或「吸合」把 PA4 置于目标电平的相反状态。需要清零时等待新基线。开始记录后再布防，确保配置和布防事件也保存在会话内。
4. **实测力阈值**在本帧标定合力达到阈值时触发。**模型预测**使用同一基线下的 16 个连续足端帧。布防后先等待一个 0–15 ms 全段低于阈值的预测窗口，随后一旦预测越阈就立即触发。两种策略共用单次触发锁存。手动输出、清零或停止均撤防。
5. 从 `nianfujiao_board.csv` 读取 `trigger_sequence`、`trigger_ready_us`、`trigger_gpio_us` 和 `trigger_latency_us`。同一触发帧会在后续状态重复报告，分析时以配置、基线与触发帧编号去重。`crossing_ms` 是预测相对源帧的越阈时距，负值表示未给出预测越阈。单独使用硬件同步判断 PA4 相对六轴接触的真实提前量。

界面主动断开时尝试发送撤防并检查确认。物理链路中断时，已布防的 STM32 继续执行本地策略。板端默认上电撤防。若一次控制循环达到 16 ms 预算，板端撤防并上报超期。

## 模型更新

从 `smzcode` 运行 `python -m training.export_stm32`。该命令读取入选的 `training/trained_models/pyramidmlp.npz`，生成 Keil 使用的单模型 FP32 常量 `Core/Src/foot_model_weights.inc` 与上位机使用的 `controller/config/board_model.json`。导出后重新编译并烧录。模型预测要求输入标定系数与训练快照一致。

## 接口

已有上行 `0x123/0x124/0x125` 与手动命令继续使用原帧格式。新增 CAN FD 标准帧 `0x126`（48 字节），所有多字节字段采用小端。

| 格式 | 字段 |
| --- | --- |
| `4B` | 版本、策略、状态、PA4 电平 |
| `2H` | 清零基线编号、配置版本 |
| `5I` | 样本帧号、采样就绪时间、触发帧号、触发帧就绪时间、PA4 写入时间 |
| `3f` | 当前标定合力、预测越阈时距、阈值 |
| `2I` | 本帧计算时间、编译时模型标识 |

策略 1 为阈值，策略 2 为预测。状态 0–5 依次为撤防、等待触发、已触发、历史积累、超期撤防、等待低于阈值的预测窗口。时间戳是 TIM2 的 32 位微秒计数，差值按无符号回绕处理。

板端设置继续使用原扩展 CAN ID `0xFFFE` 的 8 字节下行通道。载荷为 `<BBHI`，首字节 `C2`，第二字节是操作码，命令号后跟 32 位参数。操作 16 撤防，17 开始配置，18–20 传三个联合标定系数，21 传阈值，22 提交，23 布防。系数及阈值的参数按 IEEE 754 单精度解释。提交参数低字节是策略，次低字节是输出电平。布防参数低 16 位是基线版本，高 16 位是已确认的配置版本。上位机逐条等待 `0x125` 回执，提交和布防以回执为准。C2 回执的 `ready_us` 字段承载配置版本。
