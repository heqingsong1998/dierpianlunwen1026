# 时间轴重建与总法向力联合标定

从原来的 `apps/main_window.py` 启动上位机，在左侧“数据采集控制”下点击 **“离线分析：时间轴重建／总力标定”**。这个窗口可以独立使用，不需要连接设备。

## 采集后重建时间轴

1. 停止数据采集和控制器，打开离线分析窗口。
2. 点击“添加会话／父目录”，选择一次会话，或包含多次实验的 `sessions` 目录。勾选本次处理的会话，不需要的会话可取消勾选或移除。
3. 设置六轴、足端的采样周期，默认分别为 **1 ms／点、16 ms／帧**。
4. 设置每个会话的“足端起点偏移”。默认 0，表示两个文件的首点假设同时；正数表示足端首帧比六轴首点晚。例如 +5 ms 时，足端从 5、21、37… ms 开始排列。
5. 选择结果父目录，点击 **“重建时间轴并绘图”**。
6. 切换“图像预览”检查各次实验，点击“打开完整报告”查看全部图，或点击 **“打开结果目录”** 查找 CSV。

重建读取每个会话的 `nianfujiao_frames.csv`（真实足端帧）和 `liuzhouli.csv`，不用旧的足端同步配对表。原始文件不修改，每次新建一个 `analysis_日期_时间_编号` 结果子目录。结果父目录不能放在原始会话内部。

时间计算为：

```text
六轴：第 i 个点的时间 = i × 六轴周期，i 从 0 开始
足端：时间 = 从首帧开始累计的帧号步数 × 足端周期 + 起点偏移
```

足端帧号有缺口时保留时间空位，不造出缺失的信号。程序处理 uint32 帧号回绕（固件跳过 0 号），发现帧号倒退或重启则要求分段。相同帧号及 ready_us 的相同记录去重，原值冲突则报错。

每个足端时刻对应的六轴 Fz 由线性插值得到。超出六轴覆盖范围的足端帧保留在图和重建 CSV 中，参考力留空，不参与拟合。两路名义时长差异明显、帧号缺失等情况会在窗口与报告中提示。

仅重建时，红点使用当前配置中的联合总力系数，不重新拟合。

## 一键重新求标定参数

1. 选择用于标定的会话，设置周期和每次实验的起点偏移。
2. 点击 **“一键联合标定并绘图”**。
3. 查看公式、训练误差和“整次留出”误差，以及每次实验的碰撞局部图和全程图。
4. 决定采用后，点击 **“应用本次系数到控制器”**。程序先校验候选配置、备份旧配置，再更新 `controller/config/calibration.json` 并重载；其他分量的旧标定参数保留。
5. 回到主界面检查总力阈值，手动“启动／重新布防”。应用系数后控制器保持停止。

模型直接使用上传的两路原始组合信号：

```text
Fz_reference = a × Fz1_raw + b × Fz2_raw + c    # N，与六轴同号，压缩为负
Fz_total = -Fz_reference                       # N，控制总力，压缩为正
```

不额外减基线，不叠加旧单片标定，不再乘 9.8 或 1.6，不取绝对值。拟合使用所有有效配对的足端帧，各帧等权。“受力误差分组”默认 `|六轴 Fz| > 0.5 N`，只用于单独统计受力时的误差，不筛选训练点。

“整次留出”会每次保留一整次实验作为验证，其余实验拟合，然后汇总被留出的预测误差。只有一次实验时没有跨实验验证；部分折无法拟合时会明确标记。输入秩不足或高度相关、无法稳定确定三个系数时会报错。

计算和导出不会自动改变当前控制参数。改动会话勾选、周期、偏移或误差分组后，旧预览与“应用”入口会失效，需要重新计算。

## 导出文件

| 文件 | 内容 |
| --- | --- |
| `report.html` | 可直接打开的完整报告，内含各次实验的图及汇总误差 |
| `analysis.json` | 周期、偏移、源文件路径和 SHA-256、逐会话质量信息、模型与报告路径 |
| `session_summary.csv` | 帧数、配对数、帧号缺口及两路名义时长 |
| `paired_for_calibration.csv` | 每个有效足端帧的原始输入、重建时间和插值六轴参考力 |
| 各会话／`foot_reconstructed.csv` | 保留原始列，追加名义时间、参考可用标记、参考力与联合总力 |
| 各会话／`six_reconstructed.csv` | 保留原始列，追加从 0 开始的名义时间 |
| 各会话／`force_comparison.png`、`.svg` | 六轴原值连续线与足端真实帧散点，包含碰撞局部和全程 |
| `joint_fit.json` | 仅标定时生成，含系数、训练误差、逐实验留出误差及各折详情 |
| `calibration_candidate.json` | 仅标定时生成，可供检查的完整候选配置 |
| `calibration_before_apply_*.json` | 点击应用时生成的旧配置备份 |
| `last_application.json` | 最近一次成功应用的时间、模型编号和备份位置 |

重建图的横轴以六轴首次明显压缩为零点，两路一起平移以便查看。导出 CSV 仍使用从六轴首点 0 开始的时间，图的这种共同平移不会改变两路相对偏移。

## 使用范围

这是**固定周期和首点偏移假设下的快速验证工具**。它假设六轴原始点按顺序等间隔且无丢失或重复；仅凭这些文件不能证实两路真实采样同步。`ready_us` 的跨度和名义时间偏差会保存在 `analysis.json` 供检查，重建时间仍按所设固定周期计算。

报告中的红点使用本批数据拟合后的模型，是拟合内展示；评估跨实验能力应看整次留出误差，特别是受力点误差。结果默认标记为 `trial`。本流程没有自动识别最佳起点偏移、移动峰值或拉伸时间轴，也不能代替独立新实验验证或用于声称精确硬件响应时延。

## 命令行

在 `smzcode` 目录运行（把路径换成实际位置）：

```powershell
python -B -X utf8 -m controller.offline reconstruct --session 'D:\实验数据\sessions' --output 'D:\实验数据\重建结果' --six-period-ms 1 --foot-period-ms 16 --offset-ms 0
python -B -X utf8 -m controller.offline fit --session 'D:\实验数据\sessions' --output 'D:\实验数据\标定结果'
```

可重复传入 `--session`。命令行的 `--offset-ms` 对全部选中会话生效，逐会话不同偏移请用窗口设置。命令行只导出候选配置，不应用到正在使用的配置。

依赖见项目根目录 `requirements.txt`。验证命令：

```powershell
python -B -X utf8 -m unittest discover -s tests -v
```
