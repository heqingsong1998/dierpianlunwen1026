# IMU1 采集与短时速度估计

入口仍为 `apps/main_window.py`。本次启用 IMU1（HWT606）；IMU2 的旧驱动仍保留，界面未启用 IMU2。

## 操作步骤

1. 在左侧“IMU1 · HWT606”选择或输入实际串口，选择波特率，点击“连接”。默认 COM12、921600；可刷新端口列表，需与传感器实际设置一致。这些界面选择用于本次运行，下次启动的默认值仍来自 `config/default.yaml`。
2. 把 IMU 刚性固定在希望测量的运动部件上，让该部件完全静止。点击右侧 **“已确认静止：标定并将速度归零（约2秒）”**，保持静止直到出现“速度估计中”。
3. 点击“开始采集”保存实验，再启动运动。也可先开始采集，再做静止标定，以完整保存标定段；标定完成前速度留空。**开始／停止采集本身不会重置积分**，连续实验重新从静止开始时应再次归零。
4. 右侧显示三轴速度（m/s）和合速度（m/s、mm/s），例如 0.1000 m/s = 100.0 mm/s。速度是估计值；默认只显示，不参与黏附脚触发控制。
5. 停止采集后，在本次 `data/sessions/session_...` 中查看 `hwt606_1.csv` 和 `imu1_velocity_config.json`。

连接后每个有效的角度包结束一次输出周期，并要求本周期的新加速度、角速度。即使只连接 IMU1，也能估计和记录；与六轴力传感器是否连接无关。显示按 10 Hz 刷新，记录按实际输出周期进行，界面刷新不会产生重复记录。

## 时间与坐标

- 默认向 IMU1 请求 TIME、ACC、GYRO、ANGLE 输出（RSW=0x000F），RRATE=0x09，即 100 Hz。原来的 `rate: 11` 实际是 200 Hz，本次已修正 IMU1 的配置和注释。
- 默认使用每个周期的芯片时间计算积分间隔，不把六轴时间贴给 IMU，也不使用串口集中解包时的微小处理间隔积分。`timestamp_ms` 和 `host_received_ns` 保留主机接收／解析时刻，便于与其他记录参照；芯片时钟与电脑时钟尚未标定同步。
- 若设备不输出可用芯片时间，可先断开，在 IMU1 的“积分时间”选择“按输出周期估计”后重新连接。此模式按配置的名义周期积分，并在每行标记 `nominal`；它假设整周期无丢失，不能保证发现完整周期丢失。
- 速度坐标为水平局部坐标：X 沿静止标定结束时的初始航向，Y 为水平正交方向，Z 向上。它不是随 IMU 姿态转动的机体坐标，也不是两个时钟已经严格同步的证明。

## 积分方法

使用未经角度清零的原始 Roll/Pitch/Yaw，按照 `Rz(yaw) × Ry(pitch) × Rx(roll)` 将加速度从传感器坐标转到水平参考坐标。静止时标定机体系残余零偏；之后固定该零偏，旋转并去除重力（默认 9.80665 m/s²），按真实新周期做梯形积分。

```text
bias_body = 静止窗口内 mean(acc_body × g − Rᵀ × [0,0,g])
a_local = Rz(−初始yaw) × (R × (acc_body × g − bias_body) − [0,0,g])
v[k] = v[k−1] + (a_local[k−1] + a_local[k]) × dt / 2
```

使用者确认的初始速度为 0。静止窗口内检查角速度、加速度模长和零偏波动；明显运动会重置这段标定窗口。**IMU 不能仅凭低加速度区分静止和匀速，必须由使用者确认静止。** 运动期间不自动归零、不持续更新零偏，也不把小加速度一律截断，因此会保留匀速段的已有速度。

芯片时间异常、周期不完整或发现缺帧时，正在运行的速度会失效，需静止后重新标定；不会跨缺口接着显示一个看似有效的速度。显示超过 0.5 秒未收到新帧时会变成“--”。重连会开始新的 `velocity_run_id`，并重新要求静止标定。

## 保存字段

`hwt606_1.csv` 每个真实输出周期一行，包括：

| 字段 | 含义／单位 |
| --- | --- |
| `timestamp_ms`、`host_received_ns` | 主机解析时刻：Unix 毫秒、perf_counter 纳秒 |
| `sample_sequence`、`chip_time_ms`、`frame_complete` | 上位机周期计数、芯片当天毫秒、周期是否完整；sample_sequence 不是设备硬件帧号 |
| `acc_x/y/z`、`gyro_x/y/z`、`angle_x/y/z`、`temperature` | 原始加速度 g、角速度 °/s、姿态 °、温度 °C |
| `linear_acc_x/y/z` | 已补偿的局部三轴加速度，m/s² |
| `vel_x/y/z`、`speed_mps` | 局部三轴速度、有向分量；合速度大小，m/s |
| `velocity_valid`、`velocity_status` | 是否有效及状态；未标定或失效时速度数值为空，不写 0 代替 |
| `velocity_generation`、`velocity_run_id` | 本次连接内的归零编号、积分实例编号，用于分段 |
| `integration_dt_s`、`integration_time_source`、`integration_elapsed_s` | 间隔秒、chip／nominal 时间源、累计有效时间 |
| `bias_x/y/z`、`reference_yaw_deg`、`gravity_mps2`、`velocity_model_id` | 机体系零偏 m/s²、初始航向、重力常数与算法编号 |

每次采集还保存 `imu1_velocity_config.json`，记录采集开始时的端口、波特率、输出设置、算法参数和归零状态。采集中重新归零可通过 CSV 的 generation 和逐行零偏追溯。没有连接 IMU1 的会话保留表头，不补造速度。

## 适用范围与实机验收

这是一种短时积分估计，不能代替编码器或外部测速。加速度偏置、姿态误差、冲击饱和与磁场干扰都会积累成速度误差；静止标定不能消除所有动态误差。例如 0.1° 的倾斜误差会泄漏约 0.017 m/s² 的重力，一秒即可造成约 17 mm/s 的速度误差，因此 100 mm/s 量级必须实测校验。

建议先做三组检查：静止 5–10 秒观察漂移；单轴从静止加速至已知速度后保持匀速；停止后检查残余速度，并与运动平台或外部测量对照。记录 IMU 安装位置和轴向，尤其要避免将 IMU 安装在不同于目标运动体的部件上。比较碰撞前后速度时，应先验证芯片周期和两路时间关系。

当前实现通过合成姿态、加速／匀速、缺帧、协议拆包和从协议到 CSV 的无硬件测试；尚未连接实际 IMU 验收，精度不能由这些软件测试推定。
