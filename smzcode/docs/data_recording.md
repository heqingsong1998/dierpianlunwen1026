# 足端 CSV 数据记录

当前 `nianfujiao_style0.csv` 和 `nianfujiao_frames.csv` 共用以下 **31 列**。只改变上位机保存端的字段选择与命名，下位机 CAN 协议、内部 24 字段数组、标定系数和控制器计算不改变。仅新建采集会话使用新表头，已有实验文件不覆盖。

## 两个文件的记录节拍

- `nianfujiao_style0.csv`：连接六轴力时，在六轴力每条样本的主机时间轴上保存最近的足端数据。同一个足端 `sample_sequence` 可以重复多行。未连接六轴力时，按足端接收节拍保存。
- `nianfujiao_frames.csv`：每收到一帧足端 `0x123` 保存一行，显示定时器、六轴力同步配对和补充帧到达都不会额外生成主数据行。

配对记录复用缓存，不会把足端真实采样频率提高到六轴力频率。分析足端采样周期时，应使用真实帧的编号和 `ready_us`。

## 精简的字段

- 原 FZ1-_raw、FZ2-_raw 是已有法向原始量的副本，不再重复输出。
- 四个 JJJ 通道没有独立标定模型，不再输出与 raw 相同的 cal 副本。
- 正/负 Fz 标定分支作为内部中间结果保留，主表只输出每组最终的完整 Fz。
- 停用的 flag_fz、flag_fx，重复的 flag_d/输出模式及 reserved 拆分视图不再进入主表。
- `sensor_ts_ms`、`protocol_version`、`output_state` 不再作为这两个主表的额外列。协议版本和相关诊断仍见 `nianfujiao_stage_pairs.csv`、`nianfujiao_commands.csv`、`nianfujiao_feedback.csv`；这些辅助表结构不变。

## 基准版本匹配与时间

`0x123` 包含主信号、样本编号和 A；清零基准版本来自 `0x124`。记录器只按 **(sample_sequence, ready_us)** 的精确匹配补入版本，支持任意到达顺序，不会用上一样本的基准版本替代未知值。

为避免等到补充帧时重写已经落盘的 CSV，两个足端文件的待匹配行会在保存端短暂排队，最多等待 **250 ms**。主机接收时间和六轴配对时间在入记录器时已固定，等待期间不重新计时。各文件保持原始入队顺序，同步配对中的重复样本也保留。

等待缓冲每个文件最多 1000 行，基准版本缓存最多 256 个样本。补充帧缺失、等待超时或缓冲达到上限时，主数据照常写出，版本留空。停止采集时也会写完待匹配行；之后晚到的补充帧不会重复写主行。未知版本可在离线分析时，再按键与 stage_pairs 文件关联。

匹配仅影响保存，不让采集回调或控制器等待 `0x124`。传输与控制器测时字段继续保存在原来的命令、反馈和控制器事件文件中。MCU 的 `ready_us` 与电脑的 `host_received_ns` 属于不同时钟，不能直接相减作为上传时延。
