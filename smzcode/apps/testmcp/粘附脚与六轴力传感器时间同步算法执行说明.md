# 粘附脚与六轴力传感器时间同步算法执行说明

分析日期：2026-10-21。

分析入口：`smzcode/apps/main_window.py`。本文中的项目相对路径均以包含 `apps`、`core`、`drivers`、`gui` 的内层 `smzcode` 目录为根目录。

本文依据当前源代码说明实际执行过程，未连接设备测量同步误差。文中的“粘附脚”指用户自研传感器；“六轴力”指 M8128B1 六轴力传感器。

## 1. 算法的核心做法

**程序以六轴力样本的主机接收时间为基准，每处理一条六轴力样本，就读取粘附脚的最新缓存值，并给两条记录赋予相同的 `timestamp_ms`。**

可以将其称为“六轴力样本驱动的最新值配对与统一时间戳标记”。粘附脚没有新数据时，继续使用上一条数据，相当于保持最新值。

需要区分两个概念：

- **记录时间对齐**：给配对的两条记录写入相同时间戳。这是当前算法实现的行为。
- **物理采样同步**：两个传感器在同一瞬间完成测量。当前所分析的代码没有通过共同采样时钟或共同硬件触发来保证这一点。

因此，时间戳相同不能单独证明两条数据反映了完全相同的物理时刻。

## 3. 程序启动及各线程的关系

### 3.1 启动窗口并绑定记录接口

入口文件创建：

```python
window = MainWindow(config_path="config/default.yaml")
```

主窗口创建 `SensorManager` 和 `DataRecorder`，随后绑定：

```python
self.sensor_manager.record_callback_nianfujiao = self.data_recorder.write_nianfujiao_data
self.sensor_manager.record_callback_liuzhouli = self.data_recorder.write_liuzhouli_data
```

这使统一采集线程能够直接调用记录接口。记录接口负责组织 CSV 行并入队，真正的磁盘写入由另一个线程完成。

### 3.2 连接设备时就开始接收数据

粘附脚连接后，驱动启动串口读取线程，并向管理器注册数据回调。六轴力连接后，程序启动设备数据流，驱动在接收线程中读取数据并保存到队列。

管理器在连接设备时调用 `_ensure_unified_thread_started()`。因此，**设备接收和统一采集循环不需要等待点击“开始采集”才启动**。

点击“开始采集”主要是创建 CSV、设置 `is_recording = True` 并启动写盘线程。在未记录期间，记录接口被调用后会直接返回。

### 3.3 参与执行的线程

| 线程或执行通路 | 做什么 | 保存的数据 |
| --- | --- | --- |
| 粘附脚串口读取线程 | 接收并解析粘附脚帧，执行回调 | 最新一条粘附脚缓存 |
| 六轴力接收线程 | 接收六轴力帧并打时间戳 | 带时间戳的六轴力帧队列 |
| 统一采集线程 | 消费六轴力队列，计算统一时间，配对粘附脚最新值 | 提交两类 CSV 记录 |
| 后台写盘线程 | 消费记录器队列，分批写文件 | 两个 CSV 文件 |
| GUI 主线程 | 按约 10 Hz 刷新显示 | 当前也会额外提交记录，详见第 9 节 |

## 4. 粘附脚数据到达后如何处理

驱动读取串口字节，将其加入接收缓冲区，找到完整的 Style0 帧后解析其中的 24 个 `int16` 字段，并执行：

```python
self._notify_callbacks("style0", data)
```

管理器的 `_on_nianfujiao_callback()` 收到通知后：

1. 将数据转换为包含原始值、标定值和合力值的字典。
2. 记录当前主机时间。
3. 用新字典替换该类型的最新缓存。

核心代码如下：

```python
data_dict = self._convert_style0_data(data)
data_dict['sensor_ts_ms'] = int(time.time() * 1000)
self.latest_data['nianfujiao'][0] = data_dict
```

这里的 `sensor_ts_ms` 是**主机完成数据转换后执行回调这一步时的时间**，包含此前通信、缓冲、解析和线程调度的影响，并非从传感器读取的硬件采样时间。

此时字典没有统一时间字段 `timestamp_ms`，也不直接向记录器提交数据。统一时间稍后由统一采集线程加到缓存的副本上。

缓存只保留最新一条：如果两次统一采集处理之间到达多条粘附脚数据，中间数据可能被覆盖，不一定逐条进入统一记录。

对应源码：[粘附脚回调](../../core/sensor_manager.py#L547)。

## 5. 六轴力时间戳如何产生

六轴力驱动在 `_read_one_frame_blocking()` 中先寻找帧头，识别成功后立即执行：

```python
ts_ns = perf_counter_ns()
```

之后读取帧的剩余内容、解析包号和六维力数据，并将以下结构加入驱动队列：

```text
(pkg_no, ts_ns, groups)
```

字段含义如下：

- `pkg_no`：数据包编号。
- `ts_ns`：主机识别到帧头时的高精度计时值，单位为纳秒。
- `groups`：该帧中的一组或多组六轴力数据，每组为 `Fx, Fy, Fz, Mx, My, Mz`。

后续 `raw_timestamp_ns` 就来自这里的 `ts_ns`。虽然部分代码注释将其描述为“设备自身”或“设备原始采集”时间，**当前驱动实际使用的是主机 `perf_counter_ns()`**。

纳秒是计时值的单位，不能据此认定跨传感器同步精度达到纳秒。

对应源码：[六轴力帧接收](../../drivers/sensors/m8128b1.py#L773)。

## 6. 统一采集循环如何逐步执行

### 6.1 取出所有尚未处理的六轴力帧

循环优先尝试 `drain_samples()`；当前 M8128B1 驱动没有这个接口，实际使用 `read_data_with_timestamp()`，将驱动队列复制并清空。

随后把每帧的 `groups` 展开为样本列表，每个样本形如：

```text
(t_ns, pkg_no, group_index, Fx, Fy, Fz, Mx, My, Mz)
```

如果本轮没有六轴力新样本：

```python
time.sleep(0.001)
continue
```

这意味着没有六轴力样本时，本轮也不会执行统一的粘附脚配对写入。

### 6.2 用第一条六轴力样本建立时间基准

统一采集循环启动时，局部变量初始化为：

```python
t0_wall_ms = None
t0_ns = None
```

处理第一条六轴力样本时：

```python
t0_wall_ms = int(time.time() * 1000)
t0_ns = t_ns_int
```

其中 `t0_wall_ms` 是**统一线程处理第一条样本时**的系统时间，`t0_ns` 是该样本此前在接收线程获得的高精度计时值。两者在不同执行步骤获取，首次排队和处理延迟可能成为整个时间轴的固定偏移。

后续在这次统一循环运行期间保持这组基准。单独停止、再次开始 CSV 记录不会重建它；重新启动统一采集线程后才会重新初始化。

### 6.3 计算每条样本的统一时间

实际公式为：

```python
now_ms = int(t0_wall_ms + (t_ns_int - int(t0_ns)) / 1_000_000.0)
```

也就是：

```text
统一时间（毫秒）
    = 第一条样本对应的主机系统时间（毫秒）
    + 当前六轴力接收计时值与第一条接收计时值之差（纳秒）/ 1,000,000
```

例如，假设 `t0_wall_ms = 1,700,000,000,000`，`t0_ns = 5,000,000,000`：

| 当前 `t_ns` | 相对第一条的增量 | 得到的 `timestamp_ms` |
| --- | --- | --- |
| 5,000,000,000 | 0 ms | 1,700,000,000,000 |
| 5,001,000,000 | 1 ms | 1,700,000,000,001 |
| 5,002,500,000 | 2.5 ms | 1,700,000,000,002 |

以上数值仅用于解释公式。最终时间字段取整到毫秒，因此不同样本可能出现相同的 `timestamp_ms`。

### 6.4 先提交六轴力记录

程序构造六轴力字典，包含：

```python
force_data = {
    # 此处省略六维力和力矩值
    'raw_timestamp_ns': t_ns_int,
    'pkg_no': int(pkg_no),
    'group_index': int(group_idx),
    'timestamp_ms': now_ms,
}
```

更新显示缓存后，调用：

```python
self.record_callback_liuzhouli(force_data)
```

### 6.5 读取粘附脚最新缓存，提交相同时间的记录

粘附脚连接有效且缓存非空时，执行：

```python
data_nf = dict(last_data)
data_nf['timestamp_ms'] = now_ms
self.record_callback_nianfujiao(style, data_nf)
```

`dict(last_data)` 创建一个副本，因此统一时间只添加到该副本，原来的粘附脚显示缓存不会因此获得 `timestamp_ms`。

对于主采集通路中的这一次配对：

```text
六轴力记录.timestamp_ms = 粘附脚记录.timestamp_ms = now_ms
```

程序选择的是**执行这一步时最新的粘附脚缓存**，没有使用 `sensor_ts_ms` 搜索最接近六轴力时间的样本，也没有进行插值、延迟补偿或时钟漂移估计。

对应源码：[统一采集循环](../../core/sensor_manager.py#L209)。

## 7. 用一个执行例子理解“保持最新值”

下面假设已经开始记录、两设备都连接正常，且没有队列积压。表中时间是便于理解的相对统一时间，A、B 代表两条不同的粘附脚样本。

| 执行顺序 | 事件 | 粘附脚最新缓存 | 主采集通路提交的记录 |
| --- | --- | --- | --- |
| 1 | 粘附脚样本 A 到达并完成回调 | A | 只更新缓存 |
| 2 | 处理六轴力样本 F0，统一时间为 0 ms | A | F0 与 A，均标记 0 ms |
| 3 | 处理六轴力样本 F1，统一时间为 1 ms | A | F1 与 A，均标记 1 ms |
| 4 | 处理六轴力样本 F2，统一时间为 2 ms | A | F2 与 A，均标记 2 ms |
| 5 | 粘附脚样本 B 到达并完成回调 | B | 只更新缓存 |
| 6 | 处理六轴力样本 F3，统一时间为 3 ms | B | F3 与 B，均标记 3 ms |

A 在文件中出现三次，是同一次测量被重复使用，不能算作粘附脚获得了三个新的测量样本。

如果处理 F0 时六轴力队列已经积压，而粘附脚缓存已经更新到 B，F0 也可能与 B 配对，即较早的六轴力样本配上较新的粘附脚数据。这说明“最新缓存配对”与“按原始时间匹配”存在区别。

## 8. 配置策略、采样频率和保存方式

### 8.1 粘附脚是否允许重复写入

当前 `config/default.yaml` 配置为：

```yaml
nianfujiao_on_change_only: false
```

- `false`：每处理一条六轴力样本，都尝试提交一条粘附脚最新值；允许重复使用同一缓存。
- `true`：比较缓存的 `sensor_ts_ms` 与上次已处理值，相同则跳过。此时主采集通路中的两类记录数量通常不同。

虽然名称中有 `on_change`，代码检查的是**回调时间是否变化**，而不是力值是否变化。若两个回调发生在同一毫秒，也可能被当作重复数据。

### 8.2 三种“频率”不能混淆

| 项目 | 当前代码或配置 | 实际含义 |
| --- | --- | --- |
| 六轴力采样频率配置 | `sample_freq: 1000` | 向设备配置的目标频率，实际输出需要实测 |
| 管理器中的循环频率变量 | `_unified_loop_hz = 200` | 用于启动日志，当前循环没有按它执行固定周期限速 |
| GUI 显示刷新频率 | 定时器间隔 100 ms | 目标约 10 Hz 的显示刷新 |

统一采集循环的执行节奏取决于六轴力数据到达、队列积压和主机处理能力。粘附脚重复写入次数增多，并不表示其硬件采样频率提高。

### 8.3 两个 CSV 分别保存什么

记录器将数据放进各自的队列，由后台线程分批写盘：

| 文件 | 保存的时间字段 | 其他主要内容 |
| --- | --- | --- |
| `liuzhouli.csv` | `timestamp`、`timestamp_ms`、`raw_timestamp_ns` | 六维力与力矩 |
| `nianfujiao_style0.csv` | `timestamp`、`timestamp_ms` | 原始值、标定值和两个 Fz 合力 |

正常主采集通路中，`timestamp` 由 `timestamp_ms` 转成可读时间，通常不是实际写磁盘时的时间。

粘附脚的 `sensor_ts_ms` 没有写入 CSV。六轴力的 `pkg_no`、`group_index` 虽然存在于内存字典，也没有保存到当前 CSV 中。

停止记录时，程序处理剩余写入队列并关闭文件，没有再执行离线时间对齐。两个记录队列独立入队，队列满时会各自丢弃数据，因此也不能无条件保证两文件行数相同。

对应源码：[记录器](../../core/data_recorder.py#L230)。

## 9. 当前实现中影响对齐的实际问题

### 9.1 GUI 刷新通路也在写入，产生额外记录

统一采集线程已经通过直接回调提交记录，但 GUI 的两个数据显示槽函数仍然保留写入：

```python
# 粘附脚数据显示槽函数
if self.data_recorder.is_recording:
    self.data_recorder.write_nianfujiao_data(style, data)

# 六轴力数据显示槽函数
if self.data_recorder.is_recording:
    self.data_recorder.write_liuzhouli_data(data)
```

显示定时器目标约 10 Hz，满足缓存和记录条件时，这条通路会再次提交数据，产生以下结果：

1. 六轴力显示缓存已经有统一时间，因此会额外重复写入最新样本及其时间戳。
2. 粘附脚显示缓存只有 `sensor_ts_ms`，没有 `timestamp_ms`。记录器读取不到统一时间时，该列会为空，可读 `timestamp` 则退回使用当前系统时间。
3. 最终文件可能混入额外重复行和粘附脚统一时间为空的行，不能直接认定同一行号就是一对同步记录。

对应源码：[GUI 数据更新槽函数](../../gui/main_window.py#L348)、[显示信号发送](../../core/sensor_manager.py#L696)。

### 9.2 六轴力同一帧包含多组数据时，共用帧时间戳

当前驱动给每帧打一次时间戳。统一线程展开 `groups` 时，帧内每组继续使用同一个 `t_ns`，没有根据组序号和采样周期推算各自的采样时刻。

因此，“一帧多组”情况下，多个样本会共用相同的统一时间。即使每帧只有一组，毫秒取整也可能造成时间戳重复。

### 9.3 未保存粘附脚时间，无法从当前 CSV 直接计算配对时间差

两条主采集记录的 `timestamp_ms` 是由程序设置成相同值的，不能用它们相减来评估同步误差。

要检查配对时的时间差，需要保留两设备各自可比较的接收时间以及配对关系。当前 CSV 缺少粘附脚原始回调时间，也没有共同配对编号。

### 9.4 没有六轴力新样本时，不产生统一配对记录

六轴力未连接、停止输出或暂时没有新样本时，统一循环会休眠并继续等待。即使粘附脚仍在更新，也不会单独通过该循环完成配对写入。

GUI 写入通路仍可能记录粘附脚数据，但这些记录缺少统一 `timestamp_ms`，不应将其视为完成了上述配对。

## 10. 主采集通路的执行伪代码

以下代码用于说明执行顺序，省略了异常处理、日志、GUI 通路和可选姿态传感器处理，不能直接替换原程序。

```text
粘附脚串口线程：
    接收完整帧
    解析并转换数据
    添加 sensor_ts_ms = 当前主机系统时间
    覆盖粘附脚最新缓存

六轴力接收线程：
    识别帧头
    添加 t_ns = 主机 perf_counter_ns()
    读取、解析剩余帧内容
    把 (包号, t_ns, 数据组) 加入六轴力帧队列

统一采集线程：
    初始化 t0_wall_ms、t0_ns 为空
    循环：
        取出并清空六轴力帧队列
        展开每帧的数据组，得到样本列表
        如果样本列表为空：
            休眠 1 ms
            继续下一轮

        对每条六轴力样本：
            如果时间基准尚未建立：
                t0_wall_ms = 当前主机系统时间
                t0_ns = 当前样本的接收计时值

            now_ms = int(t0_wall_ms + (t_ns - t0_ns) / 1,000,000)
            为六轴力数据添加 timestamp_ms = now_ms
            提交六轴力记录

            如果粘附脚连接有效，且已有缓存：
                如果启用了回调时间去重，且回调时间未变化：
                    跳过本次粘附脚记录
                否则：
                    复制粘附脚最新缓存
                    为副本添加 timestamp_ms = now_ms
                    提交粘附脚记录

记录接口：
    如果没有开始记录：直接返回
    否则：组织 CSV 行并尝试放入对应写入队列

后台写盘线程：
    分别消费两类记录队列
    分批写入对应 CSV
```

## 11. 对当前方法的准确表述及后续改进方向

适合描述当前算法的表述是：

> 系统采用基于主机时间的软件对齐方法。以六轴力数据帧在主机端的接收计时值建立统一时间轴；处理每条六轴力样本时，读取粘附脚传感器的最新缓存数据，为两类记录赋予相同的毫秒时间戳。粘附脚数据未更新期间重复使用上一条测量值。

现有代码分析不能支持“两个传感器同步采样”或“同步误差小于 1 ms”等精度结论，这些需要额外机制和实验验证。

如果后续需要改进，优先考虑以下事项；它们是建议，并非本次已经完成的代码修改：

1. 取消 GUI 显示槽中的额外写入，统一由主采集通路提交记录。
2. 保存两设备各自的主机接收时间、样本编号和共同配对编号，保留判断配对质量的依据。
3. 为粘附脚建立带时间戳的历史队列，按时间选择样本，并设置允许的时间差和数据过期阈值。
4. 对通信延迟、缓冲积压及设备输出延迟开展测量；需要更严格的采样同步时，再结合设备能力设计共同触发或共同采样时钟。
